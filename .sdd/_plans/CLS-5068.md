# CLS-5068: [elasticsearch-bundle] Close the open Dependabot alerts

Sub-task: https://celesta.atlassian.net/browse/CLS-5068
Parent (specification): https://celesta.atlassian.net/browse/CLS-4973

## Overview

Dependabot reports 6 open alerts on master (read 2026-11-20): 1 high, 1 medium and 4 low, on `symfony/yaml`,
`symfony/cache` and `symfony/validator`. No lock file is committed, so the alerts come from the version ranges in
`composer.json`. Every Symfony requirement there is `^4.4|^5.0|^6.0|^7.0`, which still accepts vulnerable releases,
4.4 included (it has no patched release). This change narrows those ranges so that no vulnerable release of the three
alerted packages is allowed, and drops Symfony 4.4 from every Symfony requirement. The change stays within a minor
release, so the merge produces v1.7 and celesta-segment (Symfony 7.4, `^1.5`) can take it unchanged.

| Alert | Severity | Package | Scope | First patched per line (5.4 / 6.4 / 7.x) |
| --- | --- | --- | --- | --- |
| #6 | high | symfony/yaml | dev | 5.4.54 / 6.4.45 / 7.4.18 |
| #5, #4, #3 | low | symfony/yaml | dev | 5.4.52 / 6.4.40 / 7.4.12 |
| #2 | medium | symfony/cache | runtime | 5.4.52 / 6.4.40 / 7.4.12 |
| #1 | low | symfony/validator | dev | 5.4.43 / 6.4.11 / 7.1.4 |

## Acceptance criteria

- `composer.json` allows no release of `symfony/cache`, `symfony/yaml` or `symfony/validator` inside the vulnerable
  ranges of alerts #1–#6.
- No Symfony requirement in `composer.json` accepts a 4.4 release; installing with Symfony 4.4 is refused.
- The bundle still resolves with Symfony 7.4, as in celesta-segment.
- The PHPUnit suite passes with 100% coverage, as CI requires.
- No change to code, behaviour or the public API: the diff touches `composer.json` and `README.md` only.

## Architecture & Design

- Only the manifest changes. Dependabot evaluates the ranges in `composer.json`; a range whose every allowed release is
  at or above the first patched release of its line closes the alert once master carries it.
- Patched floors apply only to the three alerted packages. Symfony does not re-tag every component on each patch
  release (on Packagist `symfony/stopwatch` tops out at v5.4.45 and `symfony/dependency-injection` at v5.4.48), so a
  single floor shared by all Symfony requirements would not resolve.
- The floor for each line is the highest "first patched" version across that package's open alerts:
  - `symfony/cache`: `^5.4.52|^6.4.40|^7.4.12`
  - `symfony/yaml`: `^5.4.54|^6.4.45|^7.4.18`
  - `symfony/validator`: `^5.4.43|^6.4.11|^7.1.4`

  A caret on a patch version keeps each range inside its line's major version (`^6.4.40` is `>=6.4.40 <7.0`), so
  6.0–6.3, which have no patched release, are excluded for these three packages.
- Every other Symfony requirement drops only `^4.4` and becomes `^5.0|^6.0|^7.0`.
- No Symfony 8: a new major version is out of scope for the parent.
- Releasing: a merged pull request on master triggers `.github/workflows/release.yml`, which tags v1.7 (latest tag is
  v1.6). Nothing in this plan tags or releases.

## Testing Strategy

No PHP test is added or changed; the change is a dependency range, and the existing suite is the regression check.
Run everything inside the `esb-php` container from `CLAUDE.md`, with `esb-es` running, never on the host:

1. `composer validate --no-check-publish`: the manifest is valid.
2. `rm -rf vendor composer.lock var/cache && composer update --ignore-platform-reqs`: resolves. Then
   `composer show symfony/framework-bundle symfony/cache symfony/yaml symfony/validator`: on PHP 8.4 each resolves to
   7.4.x, at or above the floors above.
3. `php -d pcov.enabled=1 vendor/bin/phpunit --coverage-text`: all Unit and Functional tests pass, coverage 100%.
4. Symfony 7.4, as in celesta-segment:
   `composer require symfony/framework-bundle:7.4.* symfony/cache:7.4.* --dry-run --ignore-platform-reqs` resolves.
5. Symfony 4.4 is refused: `composer require symfony/framework-bundle:4.4.* --dry-run --ignore-platform-reqs` fails to
   resolve, and so does `composer require symfony/cache:4.4.* --dry-run --ignore-platform-reqs`.
6. Each vulnerable release is refused, for example
   `composer require symfony/yaml:7.4.17 --dev --dry-run --ignore-platform-reqs` and
   `composer require symfony/cache:6.4.39 --dry-run --ignore-platform-reqs` both fail to resolve.
7. Revert any `composer.json` or `composer.lock` change the dry runs left behind. No lock file is committed.

Manual, after the lead merges (outside `sdd-implement`):
`gh api 'repos/celesta-tech/celesta-elasticsearch-bundle/dependabot/alerts?state=open'` lists none of #1–#6, and tag
v1.7 exists.

## Edge Cases & Error Handling

- **A component missing the floor's version:** each floor is a version Packagist lists for that package (`symfony/cache`
  v5.4.52, v6.4.40, v7.4.12; `symfony/yaml` v5.4.54, v6.4.45, v7.4.18; `symfony/validator` v5.4.43, v6.4.11,
  v7.1.4, all checked on 2026-11-22). No floor is put on a package that has no alert.
- **Consumers on Symfony 6.0–6.3 or 7.0–7.3:** they can no longer install `symfony/cache` from this bundle's range, so
  they must stay on v1.6. The only consumer, celesta-segment, is on 7.4 and unaffected.
- **PHP 8.1 consumers:** Symfony 7.4 needs PHP 8.2; Composer picks the 6.4 or 5.4 line for them, and every line has a
  patched floor. The `php` requirement stays `^8.1`.
- **A new critical or high alert raised before CLS-4973 closes:** it is handled by amending this plan, not by the
  implementer on its own.

## Out of Scope

- Symfony 8 support.
- Bumping celesta-segment to v1.7; its own alerts cover that.
- Code that only existed for Symfony 4.4: none was found (no `Kernel::VERSION` or version checks in the code).
- The stale consumer note in `CLAUDE.md` (it says segment is locked on v1.1; it is on v1.5).
- Tagging or releasing v1.7: CI does it when the lead merges.
- `.github/dependabot.yml`.
